# Совместная разработка OSINT Platform

## Роли

| Исполнитель | Зона ответственности |
|---|---|
| Codex | Frontend, UX/UI, клиентское состояние, интеграция готового API, визуализация графа и отчётов |
| Claude | Backend, Prisma/миграции, авторизация и доступы, очереди, провайдеры, API, тесты и инфраструктура |

## Главная цель

Собрать законный OSINT-workbench для работы только с публичными источниками: пользователь создаёт расследование, добавляет сущность, запускает обогащение, видит проверяемые факты и связи, сохраняет доказательства и получает экспортируемый отчёт.

Нельзя добавлять источники украденных баз, закрытые lookup-боты, обход авторизации или функции для несанкционированного доступа к данным.

## Очередность

1. **P0 — рабочая и безопасная основа.** Claude исправляет запуск/CI, миграции, доступы, WebSocket и API-контракт. Codex параллельно готовит дизайн-систему, app shell и клиент API.
2. **P1 — сквозной сценарий.** Создание кейса → добавление сущности → enrichment → live results → dossier сущности.
3. **P2 — исследование.** Граф, findings triage, evidence, аудит, watchlists/alerts.
4. **P3 — аналитика.** Дополнительные законные источники, экспорт, STIX/CSV/PDF, scheduled rechecks и сравнение изменений.

## Правило синхронизации

- Новые или изменённые endpoint, DTO, enum и WebSocket event сначала фиксируются в `api-contract.md`.
- Backend не возвращает сырые секреты провайдеров; frontend не хранит их и не вызывает источники напрямую.
- Каждый факт должен иметь `source`, время получения, исходный payload/ссылку и confidence.
- Изменения схемы Prisma сопровождаются миграцией и тестом доступа.
- Перед передачей задачи исполнитель обновляет статус в `status.md`.

## Текущий приоритет

Сначала нужен стабильный API и один полностью работающий пользовательский поток. До этого не расширяем набор провайдеров и не делаем декоративные дашборды с выдуманными данными.
