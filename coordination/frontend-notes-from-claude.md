## Конкретные находки (файл:строка)

1. **Нет страницы логина** — искал `*login*`/`*auth*` в `apps/web/src/app`, ничего нет. Бэкенд требует JWT везде — сейчас приложение нельзя открыть залогиненным.
2. **`apps/web/src/components/dashboard/dashboard-layout.tsx:48`** — активный пункт сайдбара определяется как `item.href === '/'` (захардкожено), а не через `usePathname()`. На любой странице кроме главной подсветка сломана.
3. **`apps/web/src/components/ui/design/custom-cursor.tsx:38`** — `querySelectorAll('a, button, ...')` для hover-эффекта выполняется один раз при монтировании. `CustomCursor` живёт в persistent layout, при клиентской навигации Next.js не перемонтируется → на новых элементах любой страницы, кроме первой открытой, hover-эффект курсора не сработает. Плюс глобальный `cursor-none` — стоит проверить доступность (фокус с клавиатуры/скринридер должен видеть системный курсор или явный focus-ring).
4. **`apps/web/src/app/intelligence/page.tsx`** — кнопка "Investigate" без `onClick`, форма никуда не отправляется.
5. **`entities/page.tsx`, `logs/page.tsx`, `settings/page.tsx`** — по 9 строк, только заголовок и абзац, ни одного реального элемента интерфейса.
6. **`components.json` (shadcn/ui) подключён, но в `apps/web/src/components/ui` нет ни одного сгенерированного компонента** — только два кастомных декоративных (`custom-cursor.tsx`, `background-orbs.tsx`). Если основа интерфейса — glass-panel/дизайн-токены из `globals.css`, возможно стоит осознанно решить: либо гнуть unstyled shadcn-примитивы под этот стиль (Button/Dialog/Table/Input/Toast), либо явно отказаться от shadcn и вычистить `components.json`, чтобы не вводить в заблуждение.
7. **Нигде нет состояний загрузки/ошибки/пустых данных** — ни скелетонов, ни error boundary, ни toast. Учитывая что backend enrichment асинхронный (BullMQ + WS), пустое/промежуточное состояние — это норма, а не edge case, стоит спроектировать с самого начала, а не добавлять потом.
